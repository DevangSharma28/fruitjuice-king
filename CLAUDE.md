# Juice King Tycoon — working on this project (with Claude Code)

A 3D arcade-idle mobile game in the style of *Chainsaw Juice King: Idle Shop*, built in **Unity 6000.4.8f1** with URP 17.4, Input System 1.19 and AI Navigation 2.0.

- **Targets:** Android and iOS in portrait first. Web portals (itch.io, CrazyGames, Poki) come later.
- **Player-facing docs:** gameplay, balance and credits are in [`Assets/Game/README.md`](Assets/Game/README.md). Read it first.
- **This file:** how the code is organised and how to change it safely.

> Claude Code reads this file automatically at the start of every session in this folder. Keep it current when you change how things work.

---

## 1. Rules that matter most

1. **Everything is generated by code.** That covers scenes, prefabs, materials, meshes, textures, icons, sounds and the animator. Never hand-edit `Assets/Game/Scenes/*.unity` or anything under `Assets/Game/Generated/` or `Assets/Game/Prefabs/`: the next rebuild overwrites it. Change the builder code in `Assets/Game/Scripts/Editor/`, then rebuild (§4).
2. **One MonoBehaviour per file, and the class name must match the file name.** Otherwise components added by the builder show up as "Missing script".
3. **Exit Play mode before editing scripts.** A recompile during Play silently drops the Editor back to Edit mode.
4. **Never break existing saves.** Progress is JSON in PlayerPrefs under the key `juiceking_save_v1`.
   - Add new fields to `SaveData` (`Runtime/Core/GameManager.cs`) with safe defaults. Don't rename or remove fields.
   - Put any migration in `GameManager.Load()`, gated on `saveVersion`, and bump `GameManager.SaveVersion`.
   - Unlock ids (`"melon_juicer"`, `"t_delivery"`…) and upgrade ids are stored in saves: **never rename them**.
5. **Back up the save before play-testing, and restore it after.** Test scripts often overwrite it (§5.3).
6. **Gameplay numbers go through `Economy` (`Runtime/Core/Economy.cs`).** Don't read `Balance` directly in new code. `Economy` picks the right number for the current world.
7. **Mobile performance is a feature.**
   - Pool objects (`Pool`, the pooled `Tweener`) instead of Instantiate/Destroy in gameplay.
   - Share materials through `MatLib` (never `new Material` per object).
   - Keep props low-poly. Use the builder's `_lowSphere`/`UVSphere` rather than Unity's 768-triangle sphere.
   - Merge static props with `CombineUnder` or static batching.
   - Small decor casts no shadows.
8. **Someone may be playing in the Editor while Claude works.** Before teleporting the player or writing PlayerPrefs from a script, check `InputJoystick.IsTouching` and the player position. If someone is playing, stay read-only.

## 3. How the game fits together

### 3.1 Core loop (both worlds)

1. **Harvest.** `Chainsaw` auto-cuts the nearest ready `FruitNode`. Pieces drop as `LooseItems` and are magnet-collected into the `Carrier`.
2. **Juice.** The player drops pieces on a `DropZone`; the `Juicer` turns 2 pieces into 1 cup.
3. **Stock.** Cups are picked up from the tray's `PickupZone` and dropped on the counter's `DropZone`.
4. **Sell.** `CustomerManager` queues customers who order a random flavour. Only flavours with both an open juicer and an open field are offered.
5. **Collect.** Customers pay into the `CashPile`; the `CashZone` collects it.
6. **Unlock.** Money buys `UnlockZone` pads; each reveals objects and the next pads.

All pads are `Zone` subclasses and work by cheap distance tests (no physics triggers).

### 3.2 Worlds (expansions)

`SaveData.expansion` picks the world: 0 is the original farm, 1 is the Tropical Farm.

- **Boot.** `Boot.unity` (`LoadingScreen`) reads the save (`GameManager.PeekSavedExpansion`), synthesises the sounds (`Sfx.Warmup`), loads that world asynchronously behind the logo and progress bar, then fades out over the running game. World switches and progress resets go back through it (`LoadingScreen.LoadSavedWorld()`). The intro waits for `LoadingScreen.Busy` to clear.
- **Redirect (fallback).** Every world scene has a `GameManager` with `sceneExpansion`. If you press Play directly in a world scene whose save belongs to another world, `GameManager.Awake` loads the right scene.
- **Completion.** When every pad is unlocked and every upgrade is maxed, `ExpansionManager` shows `CompletionPopup`.
- **Switching world.** `GameManager.BeginExpansion` then archives world 0, resets per-world progress (lifetime stats are kept) and loads the next scene.
- **First visit.** `ExpansionIntro` plays a skippable camera tour driven by `CameraFollow.Peek`.
- **Scene names.** `ExpansionManager.SceneName(i)` holds the list; keep it in sync with the build settings (`JuiceKingBuilder.SetBuildScenes`).

### 3.3 Economy, upgrades, delivery

- **`Economy`** holds world-aware formulas: saw power, bag size, speed, prices, regrow time, juice time, worker bonuses, truck interval and rewards, offline rate, and the ids of helpers and mixers.
- **`Upgrades.ForWorld(world)`** returns a data-driven list of `UpgradeDef`s.
  - World 0 wraps the 5 classic upgrades (their levels live in `SaveData.sawLevel`…).
  - World 1 is an 18-upgrade tree in 6 tabs (levels in `SaveData.upIds`/`upLevels`).
  - `UpgradePanel` builds its rows and tabs from this list.
- **Delivery (world 1):**
  - `DeliveryManager` schedules trucks, generates orders (`DeliveryOrders`) and pays out.
  - It saves the active order in `SaveData.delivery`.
  - Trucks follow waypoint paths set up by `DeliveryBay`.
  - Loading happens on `DeliveryZone`.
  - Order info is shown on the 3D `TruckBoard` at the bay and in `DeliveryPopup`, opened by the parcel button (`DeliveryHUD`).
- **Tutorial.**
  - Scripted steps 0–5, then free-play guidance: the next unlock, "Upgrade ready", then "Max every upgrade…".
  - The HUD crown bar shows world progress: unlocked pads plus upgrade levels (`ExpansionManager.Progress`).

## 4. Building

**Menu `Juice King`:**

| Item | Does | When |
|---|---|---|
| **Build Everything** | art + UI cutting + imports + prefabs + **both** scenes + project settings | after changing `ArtGen`/`UIKit`/imports, or on first checkout |
| **Rebuild Scene (skip art + import)** | prefabs + **both** scenes | most builder changes |
| **Rebuild Tropical Scene** | prefabs + Tropical only | island-only changes |
| **Rebuild Boot (Loading) Scene** | the loading screen only | loading-screen changes |
| **Reset Save Data** | deletes the PlayerPrefs save | fresh start |

**The same actions from code** (useful from the CLI):

- `JuiceKing.EditorTools.JuiceKingBuilder.Run()` — Build Everything
- `RunSceneOnly()` — Rebuild Scene
- `RunTropicalOnly()` — Rebuild Tropical Scene
- `RunBootOnly()` — Rebuild Boot (Loading) Scene

Each one logs a line when it finishes:

- `[JuiceKing] Build complete`
- `[JuiceKing] Scene rebuilt`
- `[JuiceKing] Tropical rebuilt`
- `[JuiceKing] Boot rebuilt`

**Running the game:**

1. Open `Assets/Game/Scenes/Boot.unity`, the real start-up with the loading screen. You can also press Play in a world scene to skip the loading screen.
2. Set the Game view to portrait (1080×1920).
3. Press Play.

**Debug keys** (Editor and development builds only):

- `M` adds $500.
- `F9` resets progress.
- `F10` opens the world-complete popup.

## 5. Working with Claude Code

### 5.1 Unity CLI

Claude drives the running Editor through the Unity CLI (`unity`, 1.0.0-beta.8; the `com.unity.pipeline` bridge in the project). Useful commands:

```bash
unity command editor_status                        # compiling? play mode?
unity command eval --code '... return "x";'        # run C# in the Editor (returns a value)
unity command eval_file path/to/script.cs          # same, from a file
unity command editor_play | editor_stop
unity command console --level error --tail 20
unity command capture_game_view --width 540 --height 960 --save_path _cap/shot.png   # writes Assets/_cap/… — delete after
```

**Quirks**

- **Long evals time out.** They report "Main thread operation timed out after 5000ms" but still run to completion. Poll `~/Library/Logs/Unity/Editor.log` for the builder's `[JuiceKing] …` line instead of trusting the response.
- **Wait for the compile.** After editing scripts, call `AssetDatabase.Refresh()`, then wait until `Library/ScriptAssemblies/Assembly-CSharp-Editor.dll` is newer than the newest `.cs` file before calling a builder. Otherwise stale code runs.
- **Some compiles never finish.** A file touched without a content change never recompiles, so also stop waiting when the Editor has sat idle for ~20 s.
- **`Object` is ambiguous in eval code.** Write `UnityEngine.Object`.
- **Capture in portrait.** `capture_game_view` without a size returns a squashed 1280×720 image. Pass `--width 540 --height 960`.
- **UI buttons.** `simulate_pointer` doesn't reach `Mouse.current`. Press UI buttons with `button.onClick.Invoke()` via eval.
- **Keyboard.** `simulate_key --key w --action down|up` works.
- **Infinite loops.** One in an eval or builder hangs the Editor. `pkill -9 Unity`, then reopen, then delete `Assets/_Recovery`.

**Rebuild helper** (save as a local script; it isn't checked in):

```bash
#!/bin/zsh
# usage: rebuild.sh [full|tropical|<empty>=scenes]
cd "/path/to/Factory Tycoon"
L=~/Library/Logs/Unity/Editor.log
newest() { find Assets/Game/Scripts -name "*.cs" -print0 | xargs -0 stat -f "%m" | sort -n | tail -1; }
dll()    { stat -f "%m" Library/ScriptAssemblies/Assembly-CSharp-Editor.dll 2>/dev/null || echo 0; }
unity command eval --code 'UnityEditor.AssetDatabase.Refresh(); return "ok";' >/dev/null 2>&1
CS=$(newest); idle=0
for i in $(seq 1 80); do
  st=$(unity command editor_status 2>&1 | tail -1)
  if echo "$st" | grep -q '"compiling":false'; then idle=$((idle+1)); [ "$(dll)" -ge "$CS" ] || [ $idle -ge 7 ] && break; else idle=0; fi
  sleep 3
done
case "$1" in full) CALL=Run; MARK="Build complete";; tropical) CALL=RunTropicalOnly; MARK="Tropical rebuilt";; *) CALL=RunSceneOnly; MARK="Scene rebuilt";; esac
C0=$(grep -c "\[JuiceKing\] $MARK" $L)
unity command eval --code "JuiceKing.EditorTools.JuiceKingBuilder.$CALL(); return \"ok\";" >/dev/null 2>&1
for i in $(seq 1 120); do [ $(grep -c "\[JuiceKing\] $MARK" $L) -gt $C0 ] && echo REBUILT && break; sleep 3; done
grep "error CS" $L | tail -5
```

### 5.2 Suggested workflow for a change

1. Read the relevant runtime script and the builder that creates its objects.
2. Stop Play mode.
3. Edit the code.
4. Compile (the helper's wait loop).
5. Rebuild the affected scene(s).
6. Back up the save.
7. Press Play, set up a test state by editing the save JSON (see below), and capture portrait screenshots.
8. Restore the save.
9. Update `Assets/Game/README.md` if the change is player-visible.

### 5.3 Saves in tests

**Back up:**
```csharp
return UnityEngine.PlayerPrefs.GetString("juiceking_save_v1", "");
```

Keep the JSON somewhere outside the project.

**Set up a state**, for example Tropical with some pads open:
```csharp
var d = JsonUtility.FromJson<JuiceKing.SaveData>(PlayerPrefs.GetString("juiceking_save_v1", "{}"));
d.expansion = 1; d.introSeen = true; d.tutorialStep = 6; d.money = 5000;
d.unlocked = new System.Collections.Generic.List<string> { "t_upgrades", "t_mango_mixer", "t_mango_farm", "t_delivery" };
d.delivery = new JuiceKing.DeliverySave { cooldown = 3f };
PlayerPrefs.SetString("juiceking_save_v1", JsonUtility.ToJson(d)); PlayerPrefs.Save();
UnityEditor.SceneManagement.EditorSceneManager.OpenScene("Assets/Game/Scenes/Tropical.unity");
return "ok";
```

**Restore:** `PlayerPrefs.SetString("juiceking_save_v1", backupJson); PlayerPrefs.Save();`

**Watch the unlock pads.** Standing on one spends money, so don't teleport the player onto a pad by accident.

## 6. Common tasks

- **Tune numbers.**
  - Classic world: `Balance` in `Runtime/Core/Items.cs`.
  - Per-world formulas: `Economy`.
  - Upgrade costs and stats: `Upgrades.World0()` / `World1()` in `Economy.cs`.
- **Add an upgrade (world 1):**
  1. Add a `Tree(id, name, category, iconKey, baseCost, growth, maxLevel, stat)` line in `Upgrades.World1()`.
  2. Read it through `Economy` via `L(id)`.
  3. If it needs a new icon key, map it in `JuiceKingBuilder.UpgradeIconTable`.
  4. Stat strings should read "Label value" (the panel renders "Label 10 > 15").
- **Add an unlock pad:**
  - World 0: `Unlock(...)` in `Scene.cs`. World 1: `TUnlock(...)` in `Tropical.cs` (it also takes a discovery subtitle).
  - Pass the objects to reveal and the pads that come next.
  - Use a new id and never reuse an old one.
  - Open a mixer before its field.
  - If it's a helper or a mixer, add its id to `Economy.HelperIds` / `MixerIds` (offline earnings).
- **Add a fruit or juice kind:**
  1. Extend `FruitKind`/`ItemType` and every 7-entry array in `Balance` (`Items.cs`).
  2. Add slice and icon art in `ArtGen`.
  3. Add the cup visual in `JuiceKingBuilder.Assets.cs`.
  4. Add the plant in `TropicalProps`.
  5. Keep enum values stable: they are saved.
- **Add a UI sprite from the atlases:**
  1. Add `P(atlas, "name", x, y)` in `UIKit.Define()`. The seed is a pixel inside the item.
  2. Run Build Everything.
  3. Use `UIKit.Get("name")`.
  4. Check the cut with `UIKit.ContactSheet(path)`.
- **Add a sound:**
  1. Add an `SfxId` entry before `Count`.
  2. Synthesise it in `Sfx.BuildClips()` with `Make(name, duration, (t, d) => sample)`.
  3. Play it with `Sfx.Play(SfxId.X, volume, pitch)`.
- **Add a new world:**
  1. Add a scene name to `ExpansionManager.Scenes`.
  2. Add a builder and include it in `SetBuildScenes`.
  3. Set `sceneExpansion` on its `GameManager`.
  4. Add world branches in `Economy` and `Upgrades.ForWorld`.
  5. Set `nextExpansion` on the previous world's `ExpansionManager`.

## 7. Checks before calling a change done

- It compiles, and a rebuild logs no `Exception` or `error CS`.
- Play mode runs in **both** worlds with an empty console (the Unity AI/licensing errors can be ignored).
- An old save still loads. Test with a world-0 save that has no new fields.
- Portrait screenshots look right:
  - HUD elements don't overlap;
  - text fits its box;
  - 3D labels aren't hidden behind props from the gameplay camera.
- No per-frame allocations in `Update` loops. Draw calls roughly unchanged (read `UnityEditor.UnityStats` via reflection: `setPassCalls`, `drawCalls`, `triangles`).

## 8. Known gaps and next steps

- **Ads are simulated.** `Ads.Provider` is null, so the `AdOverlay` counts down instead. To ship, implement `IRewardedAdProvider` for the chosen network (LevelPlay or Unity Ads). Ask the owner which network first.
- **Bundle identifier** and signing are not set up for store builds.
- **Web portals.** The hooks in `Core/Platform.cs` are ready. A landscape HUD pass is still needed for desktop web.
- **Not play-tested yet:**
  - a truck timing out (it pays shop price for what was loaded);
  - "Stay a bit longer" and the NEW WORLD button;
  - offline earnings and the FINISH ad button in world 1.
- **No version control yet.** Consider git with a Unity `.gitignore` that excludes `Library/`, `Temp/`, `Logs/` and `UserSettings/`. Generated assets can be committed, or rebuilt with Build Everything.
